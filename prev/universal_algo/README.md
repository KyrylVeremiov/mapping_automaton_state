# state_mapper

Maps the current state of an **old** DFA A to a state of a **new** DFA B **by history**, when no log of past events is available.

Python 3.8+, no dependencies. Partial and completely defined automata are handled in the same way (a complete automaton is a partial one in which every transition is defined). Drawing PNG pictures additionally requires [Graphviz](https://graphviz.org/download/) (`dot` on your PATH).

## Idea

The real history that brought A into state `q` is unknown. All we know is that it belongs to the set of histories

    H_A(q) = { w : A, started in start_A and reading w, ends in q }

We replay **all** of these words in B and look at where B ends up:

    N(q) = { δ_B(start_B, w) : w ∈ H_A(q) }     (δ undefined = a separate value, "stuck")

| N(q) | Status | Meaning |
|---|---|---|
| exactly one real state `p` | `UNIQUE` | the answer is unambiguous: it is `p` |
| ≥ 2 real states | `AMBIGUOUS` | B tells apart histories that A merged into `q` |
| contains "stuck" | `STUCK` | B cannot replay some of the histories (the event is not allowed) |
| empty | `UNREACHABLE` | `q` cannot be reached from A's start, so it has no history |
| (`q` is a declared trap of A, mode `forbid-both`) | `TRAP` | not mapped by history, see "Trap modes" |

Words are not enumerated (there are infinitely many because of cycles). Instead, the program runs a BFS over the product A × B: a pair `(a, b)` is reachable if and only if some word leads A to `a` and B to `b`. The pairs `(q, *)` give N(q). The BFS also returns the shortest word for every pair, which serves as evidence in the explanation.

**Complexity:** time O((m+1)·E) ≤ O(n·m·k), memory O(n·m), where n and E are measured after trimming the states of A that cannot lead to `q`, m = |Q_B|, k = |Σ|. `map_all` computes all states of A in a single traversal with the same bound.

## Quick start

```python
from state_mapper import DFA, map_state, map_all, format_table

old = DFA.from_text("start=s; s -a-> x; s -b-> y; x -c-> q; y -c-> q")
new = DFA.from_text("start=S; S -a-> X; S -b-> Y; X -c-> P; Y -c-> P")

res = map_state(old, "q", new)
print(res.status, res.answer)     # Status.UNIQUE P
print(res.explain())              # detailed explanation with evidence

print(format_table(map_all(old, new)))   # mapping for every state of A
```

An automaton can be given as text (`start=NAME; src -event-> dst; ...`, see "Wildcard events" below for `*` and `!a`), as a list of transitions `DFA("s", [("s","a","x"), ...])`, or as a JSON file `{"start": "s", "transitions": [["s","a","x"], ["x","!a","s"], ...]}` (optional keys: `"states"`, `"alphabet"`). State and event names must not contain whitespace.

## API

- `map_state(old, current, new, *, lenient=False, new_traps=(), old_traps=(), trap_mode="ordinary") -> MappingResult`
- `map_all(old, new, *, lenient=False, new_traps=(), old_traps=(), trap_mode="ordinary") -> {state: MappingResult}`
- `format_table(results) -> str`
- `distinguishing_word(dfa, p1, p2, forbidden=())`: the shortest event sequence that is allowed from exactly one of the two states (or `None`)
- `DFA.is_complete(alphabet=None)`, `DFA.completed(alphabet=None, sink="sink")`, `DFA.is_absorbing(state)`, `DFA.expanded(alphabet)`
- `parse_events("a,b" | "*" | "!a,!b")`, `Except(names)`, `ANY`, `OTHER`, `TrapMode`

`MappingResult`:

| Field | Meaning |
|---|---|
| `status` | `Status.UNIQUE / AMBIGUOUS / STUCK / UNREACHABLE / TRAP` |
| `answer` | the state of B (only for `UNIQUE`) |
| `candidates` | `{state of B: shortest history}` for every real element of N(q) |
| `stuck` | a `StuckWitness` (a history that B cannot replay, the event on which it gets stuck, and `into_trap` if that event leads into a forbidden trap) or `None` |
| `notes` | hints about possibly misleading answers (see "Trap modes"); also printed by `explain()`; `note_summaries` gives one-line versions |
| `explain()` | textual explanation; `short()` gives a one-line summary |

**Strict and lenient mode.** By default (`lenient=False`), any history that B cannot replay makes the result `STUCK`, even if all other histories agree on a single `p`. With `lenient=True`, such a case returns `UNIQUE(p)` together with a warning (`stuck` stays populated). If no history can be replayed at all, the result is still `STUCK`.

## Complete automata and trap modes

A DFA is *complete* if every state reacts to every event. There is no "undefined transition" there: a forbidden event leads to a **trap (sink) state**, and an "ignored" event is a self-loop. The program treats complete and partial automata in the same way: a trap is **an ordinary state by default**. Histories may lead into it, and it can be the answer `p` or the asked state `q`.

You may *declare* traps (`new_traps` for B, `old_traps` for A) and choose what the declaration means with `trap_mode`:

| `trap_mode` | Meaning |
|---|---|
| `ordinary` (default) | traps are ordinary states: the declaration changes nothing in the logic (it only adds hints and drawings) |
| `forbid-new` | entering a declared trap of B means "B does not allow this event", exactly like a missing transition: such histories are not replayable, so the result becomes `STUCK` |
| `forbid-both` | additionally, traps of A are not mapped: a declared trap asked as `q` gives `TRAP`, and a step of A into a declared trap is not a valid history step (histories through it are dropped) |

```python
res = map_state(old, "triggered", new, new_traps={"fault"}, trap_mode="forbid-new")
res = map_state(old, "err", new, old_traps={"err"}, new_traps={"dead"}, trap_mode="forbid-both")  # -> TRAP
```

The explanation then says *"it leads to the trap state 'fault'"*. CLI: `--new-trap`, `--old-trap` (repeatable), `--trap-mode`.

- **Without a declaration the answer can mislead**: if every history ends in a trap, the result looks `UNIQUE` although B actually forbids it. The program prints a `NOTE` when the chosen B state is absorbing while the old state can still move on (the program cannot tell an error trap from a legitimate final state such as `cancelled` by structure alone).
- Comparing the future of ambiguous candidates (the "how these B states differ" lines) works for a complete B only after its traps are declared and forbidden, because a complete automaton formally allows every event everywhere.
- `DFA.completed(sink=...)` turns a partial automaton into a complete one. Mapping into the completed copy with `new_traps={sink}, trap_mode="forbid-new"` gives the same result as mapping into the partial automaton (checked by the tests).
- A trap of A asked about by history is not meaningful: its "history" is just a pile of invalid event sequences. Use `forbid-both` to refuse such a question explicitly (`TRAP`), or map it by hand (trap → trap).

## Wildcard events: `*` and `!a`

In the text format (and in JSON) a transition may use a wildcard instead of an event name:

```
start=idle; idle -arm-> armed; idle -!arm-> idle;      # every event except arm
armed -fire-> fault; armed -!fire-> armed; fault -*-> fault   # '*' = every event
```

- `s -*-> t` fires on every event; `s -!a-> t` on every event except `a`; `s -!a,!b-> t` except `a` and `b` (`!x` cannot be mixed with plain names). Several plain events are written `s -a,b-> t`.
- An explicit transition of the same state **wins** over a wildcard ("else" semantics). A state may have only one wildcard target.
- Wildcards also cover events that nobody names. They are represented by the pseudo event `<other>` (it can appear in witness words). `alphabet=a,b,c` closes the universe of events and removes `<other>`.
- Both automata are resolved against one common set of events: everything either of them names, plus `<other>` (unless an alphabet is declared).

## CLI

```
python state_mapper.py order_v1.json order_v2.json paid        # one state
python state_mapper.py order_v1.json order_v2.json --all       # table for all states
python state_mapper.py old.json new.json shipped --lenient
python state_mapper.py old.json new.json triggered --new-trap fault --trap-mode forbid-new
```

Exit code: `0` for `UNIQUE`, `1` otherwise.

## Visualization

```
python visualize.py --example L3-06 -o picture.png         # an example from examples.py
python visualize.py --all-examples images/                 # PNG for all 61 examples
python visualize.py old.json new.json STATE -o out.png     # your own automata (+ --lenient, --new-trap S, --old-trap S, --trap-mode M, --dot out.dot)
```

From code: `map_state(old, q, new).save_png("out.png")`, or `.to_dot()` for the DOT text.

In the picture the old automaton is always on top and the new one below it.

| Element | Meaning |
|---|---|
| gold node with a double ring, `(current)` | current state of A |
| coloured node, `(match)` / `(candidate)` | corresponding state of B (green: the unique answer; other colours: candidates when the result is ambiguous) |
| dashed arrow from A to B | the correspondence, with an example history |
| thick coloured edges | the shortest history to each candidate, drawn in A and in B with the same colour (an edge shared by several histories is drawn as parallel lines) |
| red edges and a red box | a history that B cannot replay and the place where it gets stuck |
| dashed node `(trap)` | a declared trap; pale red fill = forbidden by the trap mode, and the red edge leads into it |
| `*` / `!x` on an edge | for automata with wildcards: the edge covers every event / every event but `x` |
| orange `NOTE` line | the chosen B state looks like an undeclared trap |
| grey nodes and edges | not on any history of the current state |

Only the shortest history per candidate is highlighted. The algorithm checks all the other histories, but they are not marked in the picture.

## Limitations

- Deterministic automata only. For NFAs the history is ambiguous by itself, and the problem becomes PSPACE-hard.
- Accepting states are ignored; only the transition structure (the "past") is used. For Mealy/Moore machines, encode the (input, output) pair as a single symbol.
- "Correct" here means "correct for every possible history". If you only need the most likely answer, then for `AMBIGUOUS` the choice has to be made with external data (frequencies, a policy, asking the user).
- The program cannot tell "B forbids the event" from "the event is intentionally absent", and it cannot tell an error trap from a legitimate absorbing state. For a completely defined B you declare the traps yourself (`new_traps` + `trap_mode`); the `NOTE` is only a heuristic.
- A trap of A that is not absorbing is dropped from histories only in mode `forbid-both`; in the other modes it is an ordinary state.
- Wildcards resolve against the events that are named somewhere (plus `<other>`); two wildcard transitions of one state with different targets are rejected.
